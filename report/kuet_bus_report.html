KUET Bus Smart Campus Bus Tracking & Management System

1Abstract

Campus transportation at Khulna University of Engineering & Technology (KUET) has historically relied on physical notice boards and word-of-mouth for bus schedule dissemination, with no real-time information available to students or staff. KUET Bus is a mobile application developed for Android using the Flutter framework that digitizes and modernizes the entire campus transport ecosystem.

The system enables real-time bus location tracking on an interactive map, dynamic schedule browsing, role-based administration, and instant push notifications for schedule changes. It incorporates an AI-powered chatbot that answers natural-language queries about routes and timings, an A* pathfinding algorithm for visualizing optimal routes on the Khulna city road network, and a fully personalized user profile system with photo upload. Administrators are equipped with a dedicated dashboard to manage buses, routes, schedules, and notices — including AI-assisted schedule extraction.

The application is built on a robust Firebase backend for real-time data synchronization, authentication, cloud storage, and push messaging. KUET Bus significantly reduces student uncertainty around campus transport, improves administrative efficiency, and lays the digital foundation for a smarter, data-driven campus mobility experience.

2Introduction

2.1 Background

Khulna University of Engineering & Technology is one of the premier public technical universities in Bangladesh, with a large student body and faculty distributed across a sprawling campus. The university operates a fleet of buses that ferry students and staff between campus and major city locations daily. Despite the scale of this service, there has been no centralized digital platform for students to track buses in real time, access reliable schedules, or receive timely notifications about changes — creating daily friction and uncertainty for thousands of commuters.

2.2 Problem Statement

The absence of a dedicated digital transport management system at KUET creates the following operational pain points:

  • No real-time bus visibility: Students have no way of knowing a bus's current location, estimated arrival, or whether it is running on time.
  • Manual schedule distribution: Timetables are distributed through physical boards and informal messaging, leading to inconsistency and missed updates.
  • No automated notifications: Changes during Ramadan, holidays, or maintenance are communicated reactively rather than proactively.
  • No administrative control panel: Bus administrators lack a unified digital tool to manage fleet information, publish notices, and update schedules efficiently.
  • No personalized student experience: There is no user-specific interface preventing targeted communication or preference settings.

2.3 Objectives

  1. Develop a real-time bus tracking system using GPS and Firebase Firestore live streams.
  2. Provide students with a reliable, browsable daily bus schedule interface.
  3. Implement role-based access control separating student and administrator experiences.
  4. Deliver push notifications for schedule updates using Firebase Cloud Messaging.
  5. Integrate an AI chatbot capable of answering transport-related queries in natural language.
  6. Build an administrator dashboard for complete fleet and schedule management.
  7. Implement A* pathfinding on the Khulna city road network as a route visualization tool.
  8. Create a personalized user profile system with photo upload and persistent preferences.

2.4 Scope

KUET Bus covers the full lifecycle of campus transport interaction — from student authentication and profile management to real-time map tracking, schedule lookup, notice reading, and AI-assisted queries. The admin module supports complete CRUD operations on all transport data. The application targets Android devices (API level 21+) and is built with Flutter's cross-platform architecture, enabling straightforward future extension to iOS.

4Features & Functionality

A  ·  Authentication & User Management

The application opens to a splash screen that silently checks Firebase Auth state. Authenticated users proceed directly to the main shell; others land on the Login screen.

  • Email & Password — standard Firebase authentication flow with signup and login screens.
  • Google Sign-In — one-tap OAuth 2.0 via google_sign_in; account created automatically on first sign-in.
  • Profile Review Screen — pre-fills KUET ID (extracted via regex from email local part) and derived batch year for new users to confirm before account creation.
  • Role-based access — a role field ("student" or "admin") on the Firestore user document drives navigation and feature visibility app-wide.

B  ·  User Profile

A rich, fully editable profile screen surfaces all personal and academic information.

  • Photo upload: Tapping the avatar opens the device gallery (image_picker). The image is compressed (512×512, 80% quality) and uploaded to Firebase Storage. The download URL is persisted to Firestore and rendered as a circular NetworkImage.
  • Edit Profile sheet: A modal bottom sheet exposes editable fields — Full Name, Phone Number, Blood Group, Hometown — saved back to Firestore on confirmation.
  • Read-only fields: Email, KUET ID, Department, and Batch (set at registration) are displayed but protected from modification.
  • Real-time sync: Profile data is fetched from Firestore on screen load and refreshed immediately after any edit.

C  ·  Live Bus Tracking

An interactive OpenStreetMap-powered screen provides real-time bus visibility across the KUET–Khulna corridor.

  • Live bus marker: A maroon circular marker with a bus icon is positioned at coordinates streamed live from Firestore's bus_locations collection via a StreamSubscription.
  • Campus destination pin: A fixed green school-icon marker at 22.9000°N, 89.5012°E marks the KUET campus.
  • User GPS location: The blue my_location button invokes Geolocator.getCurrentPosition() after requesting ACCESS_FINE_LOCATION. A blue person-pin is placed at the user's coordinates and the camera moves there.
  • Center on bus: A dedicated maroon directions_bus button always re-centers the map on the live bus, no matter how far the user has panned.
  • Back navigation: A back arrow button appears automatically when the screen is accessed via a navigation push, preventing users from getting stranded on the map.

D  ·  A* Pathfinding & Route Demo

A switchable routing mode transforms the Live Map into an interactive shortest-path demonstration.

  • The Khulna city road network is loaded from a local GeoJSON asset into an in-memory adjacency graph.
  • Two-tap selection: first tap sets the start node (red "S" pin), second tap sets the destination (blue "D" pin) — both snapped to the nearest road node via Haversine distance.
  • The A* algorithm computes the shortest path synchronously; a green polyline is rendered on the map.
  • A status banner displays route distance (km/m), nodes explored, and elapsed computation time (ms).
  • A third tap resets the selection and starts a new route. Haptic feedback confirms each tap.

E  ·  Bus Schedule

  • Date picker for browsing timetables by any specific date.
  • Toggle between Normal and Ramadan schedule variants.
  • Active buses are visually emphasized; inactive services are dimmed.
  • Color-coded route legend for quick route identification.
  • Live Firestore stream — admin updates appear instantly without requiring a refresh.

F  ·  Notices & Announcements

  • Real-time notice feed ordered by creation time, streamed from Firestore.
  • Three-tab filter: All Alerts Events
  • Notice cards show title, body excerpt, tag, and relative timestamp.
  • Latest three notices appear in a scrollable carousel on the Home dashboard.

G  ·  AI Chatbot Assistant

A floating chatbot widget powered by the OpenAI API provides a natural-language transport assistant.

  • Before responding, the chatbot fetches the current day's live schedule from Firestore as context, grounding answers in real data.
  • Handles queries such as: "What time does the next bus to campus leave?", "Is there a Boyra route bus today?", "What is the Ramadan schedule?"
  • The widget floats above all screens and can be expanded or dismissed without interrupting navigation.

H  ·  Push Notifications (FCM)

End-to-end push notification pipeline for schedule update alerts:

  1. Admin posts a schedule change or AI extraction is submitted.
  2. Firebase Cloud Messaging delivers a push to all registered student devices.
  3. flutter_local_notifications displays the notification in the system tray.
  4. Tapping the notification deep-links to the Pending Schedule Screen for the relevant date.

A global navigatorKey in app.dart enables correct deep-link routing even when the app is launched cold from a notification tap.

Navigation Architecture

  • IndexedStack with 5 tabs preserves full screen state across tab switches — no rebuilds when switching.
  • AppThemeScope (InheritedNotifier<AppThemeNotifier>) propagates the dark/light theme to every widget in the tree without manual passing.
  • A global navigatorKey in app.dart enables deep-link routing from FCM background notification taps, even when the app is cold-launched.
  • Admin users receive a 5th "Admin Dashboard" tab injected at index 2, replacing the Live Map tab available to students.

7Security & Access Control

Firebase Firestore Security Rules enforce role-based access at the database level, independent of any client-side enforcement. Students may read shared collections (buses, routes, schedules, notices, bus_locations) and their own users document. Write access to all administrative collections is restricted to users whose Firestore role field equals "admin".

MechanismPurpose
user.getIdToken(true) before readsForces token refresh — ensures security rules see a fresh authenticated context
Firestore transactions for bus/route upsertPrevents race conditions; enforces uniqueness atomically across concurrent admin writes
Index collections (unique_bus_numbers, unique_route_names)Database-level deduplication independent of client validation

Key Design Decisions

  • Bottom navigation: 5-tab bar with a raised circular center button for the Notices tab (highest-frequency action), styled with a maroon pill on active tabs.
  • IndexedStack: Preserves scroll position and data for each tab independently — switching tabs does not trigger a rebuild or re-fetch.
  • Theming: Custom AppThemeNotifier wrapped in AppThemeScope (InheritedNotifier) — any widget calls AppThemeData.of(context) for instant, consistent theming.
  • Animations: Pulsing live-tracking dot (900ms scale loop), inline upload spinners, route stats banner transitions.
  • Haptics: HapticFeedback.selectionClick() on map taps in A* mode.

11Conclusion

KUET Bus successfully addresses a long-standing gap in campus transport management at Khulna University of Engineering & Technology. By combining real-time Firebase data synchronization, interactive OpenStreetMap-based tracking, AI-assisted schedule management, and push notification delivery, the application transforms a previously manual and fragmented experience into a cohesive, always-available digital service.

The project demonstrates the viability of Flutter and Firebase as a full-stack mobile development platform for production-quality institutional applications. The integration of the A* pathfinding algorithm with a real road network asset proves that computationally meaningful algorithms can be embedded in mobile apps with excellent performance. The AI chatbot and schedule extraction features illustrate how large language models can be practically applied to reduce administrative burden in academic settings.

Key lessons learned include the importance of atomic database transactions for data integrity, the power of Flutter's InheritedNotifier pattern for efficient state propagation, and the value of designing role-based navigation as a first-class architectural concern rather than an afterthought. KUET Bus is a functional, scalable, and extensible foundation for a smarter campus transport ecosystem — one that can grow with the university as real IoT hardware and expanded services are introduced.
